## 当前 cross-view GRPO 边界

### 六用户27B运行边界

沿用已验证的单H200 Policy/Judge交替运行，不能未经显存验证改为同时驻留。用户已批准微批2/累积2/G4测量及必要时的反馈式keeper，已有授权不重复询问。保留原数据、reward、学习率曲线和完整断点；通用取消预防及恢复要求统一见Torch规则第5节。JobID、取消事件和现场利用率放当前Runbook/manifest，不作为长期规则中的当前状态。

### 六用户27B训练正确性与完整退火（2026-10-07侧交接并入）

用户后续明确修正：四个学习率组先完成总计100步并做同设置固定比较，只让表现较好的1–2组继续到总计200步；明显领先时只续一组，差距接近时最多两组。这里不是额外200步、不是总计400步，也不把四组都自动扩至200。200步完成调度不自动证明收敛。用户已确认第一条LoRA路线：G4、q_proj/v_proj/in_proj_qkv、r8/a16、视觉与aligner冻结；该模块清单不再重复询问确认。先刷新学习率实验进度及真实剩余时长，若接近结束则等较优LR确定后启动LoRA；当前未授权改G8，具体实验调度与预算仍据实安排。

先核验实际候选/奖励/媒体的组内对齐、优势与梯度方向、生成端LoRA同步和独立重载，以及冻结Judge的方向与区分能力，再扩大超参搜索。有限梯度、非零LoRA和完整断点只证明发生更新，不证明学习方向正确。损失类型与归一化以Torch实际安装版本为准，不套用最新文档默认值。

G和LoRA覆盖是优先讨论的搜索维度，具体新G值和模块清单必须与用户确认后修改；微批2/累积2/G4并不是G8。修改模块前先统计真实模型层型、现有注入位置/参数数及vLLM适配器支持，保持视觉与对齐模块冻结，不盲目改成全部线性层。

已有max_steps200/stop100/warmup10/min_lr_rate0.1的100步结果，学习率仍约为峰值58.7%，是中途状态。新100步完整退火应从同一基座新LoRA开始，调度总长100、终点为峰值10%；不得重标或简单缩短已有200步断点的调度。用户已允许在确有必要时针对具体配置保留原曲线继续到200，再比较同设置基座/100/200端点；不自动延长全部四组，不无上限延长到出现正结果，先核实累计H200预算。100步中途均值未升不等于GRPO无效，完整退火也不自动证明收敛或质量改善。

排查不得修改其他活动实验、重复提交或删除claim。读取本次manifest、日志和已有产物，检查与改动相匹配。验证6个提问者来自一个视频窗口；24个生成槽位不等于24个独立视频或同样的QA。若题目重新生成，配对对象是输入/种子/槽位，不是固定题目。

### qa_cross_view_relation 特定实验

- 使用 `qa_cross_view_relation` 时，其 text-only judge 负责格式、自然度、内部一致性、非浅层关系和文本关系强度；除非实验版本明确改变，不负责视频 groundedness 或真实 answerability。
- `deterministic.py` 是候选资格检查/路由，不是奖励公式中的独立加权项。
- 任何阻断性内部一致性错误、问题—答案类型错位、语义重复选项或浅层活动问题，都必须通过可审计规则限制最终奖励，不能仅依赖 judge 的总体印象。
- 训练数据必须报告独立 `evidence_id` 数量、question type 分布和 held-out 划分。单一视频对上的 reward 上升不能称为跨 clip 泛化。
- 失败实验应保留在明确的 archived 路径；活跃实验不得反向依赖 archived 实现。
