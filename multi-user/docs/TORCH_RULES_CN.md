# Torch 操作统一规则

2026-10-07 按用户要求合并。本文是本工作区唯一的通用 Torch 规则入口，覆盖旧连接 SOP、通用教程、Meta 规则、Runbook 模板和 GRPO 通用远程约束中的重复或冲突条款。项目的实验目标、数据合同和用户已批准的配置仍按项目规则、当前任务和实际代码执行。

## 1. 阅读范围：首次读一次，后续按变化读取

- 新上下文首次进行 Torch 操作时，完整读取本文一次；同一上下文中内容未变且仍完整可用，不重复全文阅读。文件变更、上下文压缩丢失关键内容或出现冲突时，重新读本文。
- 查状态：读取当前任务的 JobID 清单、精确日志和结果。无需为一次只读查询重读全部源码、测试、环境教程或历史实验报告。
- 新建或修改提交：读取对应项目的实验约定、真实入口/参数、相关 `.sbatch`、配置、数据及受影响检查。阅读与本次变更有关的部分，不要求遍历整个测试或实验目录。
- 当前 Runbook 只读取最新执行记录及本次需要的操作段；历史失败或旧版本仅在排查相关问题时查阅。用户明确要求完整读取某份交接时仍照办。
- 旧文件保留兼容索引，不再构成额外必读链。本文缺失或不能完整读取时说明 `STOP`；已失效的旧教程链接不应阻断无关的状态查询。

## 3. 提交与资源

- 提交前检查真实 Git 根目录、分支、版本、dirty state、脚本、输入及当前远端资源。account、partition、QOS、路径和数据计数必须来自实际文件/查询或用户输入；冲突未解决不能提交。不在登录节点运行训练、重安装或大规模下载。
- 默认让 Slurm 自动路由，不固定节点或手工指定分区。只有用户指定准确节点，且现场资源兼容时才可固定节点；已验证的特殊调度需求以当前任务为准。
- 所有 `sbatch` 使用 `--parsable`，去掉可能的 cluster 后缀后取得数字 JobID，立即保存时间戳提交清单。配置、日志和输出以本次 JobID 隔离；监控从清单派生，不使用 `latest_*` 或共享固定目录冒充当前结果。保留现有防重复提交标记。
- 每个提交块在全新登录 shell 内独立成立，声明项目、环境、模型、数据、断点/前级产物、资源及路径，并检查直接依赖。供用户粘贴的登录命令不裸用 `exit`、`logout`、`exec`、`|| exit 1` 或全局严格模式；失败打印 `STOP/MISSING` 并跳过依赖步骤。严格模式限 `.sbatch` 或明确子 shell。
- 时限按真实单步/单工作单元耗时、剩余数量及启动/验证开销估算，通常保留15%–25%余量。缺少可比证据或申请超过线性估计1.5倍时，说明假设并按已有授权确认，不直接沿用8/24小时默认值。固定通过数必须计入实际通过率；允许部分结果时正常保存 `partial`，不靠超时强杀保存。

## 4. 环境、存储与必要验证

- 优先复用已验证的代码、模型、环境、数据和断点。训练与推理环境分别检查；只重验受影响部分。首次环境验证包括真实CLI、包入口、依赖闭包及实际所需的编译工具；之后不为无关的只读查询重复 `pip check` 或GPU测试。
- 正式作业必须在模型加载前将 `HOME`、`XDG_CACHE_HOME`、`HF_HOME`、`HF_DATASETS_CACHE`、`MODELSCOPE_CACHE`、`TORCH_HOME`、`TRITON_CACHE_DIR`、`TORCHINDUCTOR_CACHE_DIR`、`VLLM_CACHE_ROOT`、`CUDA_CACHE_PATH`、`FLASHINFER_WORKSPACE_BASE`、`TMPDIR/TMP/TEMP` 封闭到当前作业的 scratch，并保存通过的 `storage_preflight.json`：绝对路径、允许范围、可写及剩余空间。模型/媒体可以只读复用公共 scratch；运行时写盘不得落入原 home、`/tmp` 或历史缓存。
- vLLM 禁止用遥测写原 home，设置 `VLLM_NO_USAGE_STATS=1`。媒体任务在任何解码器、processor或模型导入前，同时设置 FFmpeg 的 `PATH` 和 `LD_LIBRARY_PATH`；首次或媒体依赖变化时验证真实解码及与正式调用一致的批量、角色/字段顺序、媒体和占位符。
- 只有创建/调整 Conda 时才检查插件和下载细节：封闭 home/cache；`CONDA_NO_PLUGINS=true` 与 `CONDA_SOLVER=classic` 成对使用，创建命令明确 classic；包缓存用 `CONDA_PKGS_DIRS`，不使用已知失效的 `conda config --env --set pkgs_dirs`。模型下载入口匹配实际安装版本，不能用过时CLI提示当成功。
- 新模型、媒体、Judge或GPU后端存在未覆盖的运行风险时，先做一次最小运行验证，不让完整训练承担首次验证。CPU测试、静态检查或同链路证据足够时直接正式执行；不得默认串联 reviewer-only、1-step、5-step、短/长 probe等台阶。已经证明通过的部分不重复；失败后只验证修复所对应的边界。
- Judge必须真实可用且输出通过实际schema。HTTP成功不能代替合法奖励；不得伪造奖励绕过服务失败。不得按位置猜候选ID；修复/重试次数和失败处理遵守实际接口。数据划分、组内候选/奖励/媒体对应与评价分母必须实际核验，不能只看文件存在。
- GRPO更新验收按实际算法检查有效候选/奖励、组内方差、真实优化器步数、有限loss/梯度、adapter变化及重载；恢复还须检查完整状态及LR连续。工程更新、学习方向正确和质量改善分别验证，不互相代替。

## 5. GPU利用率：每次提交前预防

- GPU作业每次提交前核对官网当前取消/警告阈值，按实际节点规则配置预防措施。优先提高真实工作吞吐：批量、缓存、CPU准备重叠和显存可控的真实并发；不改变未经批准的G、有效批量、媒体、prompt、reward或训练目标，不用无意义重复计算冒充吞吐优化。
- 同GPU的Policy/Judge未经显存验证不能同时驻留。扩大微批或并发存在新显存风险时做一次必要的显存/吞吐测量；OOM或退化时保留失败记录并按证据回退，不反复原样重投。
- 实际优化仍不足且已有用户授权时，提交前配置反馈式 keeper，运行不足时主动响应，不等取消。它从启动开始逐卡记录利用率、显存、阶段及真实吞吐，不依赖等待7200秒或旧显存门槛。纯CPU作业不套GPU规则。
- 保护同时考虑短时下探、10/30/60/120分钟及累计窗口；启动不足窗口时报告已有时长。目标高于取消阈值并留余量，有警告阈值时优先超过警告值。长窗口80%等均值不能排除短时风险；样本有间隔时不把样本数量当精确秒数。统计窗口未知时明确记录边界，不保证绝不会取消。
- keeper使用低优先级计算流、有限占空比、明确reserve/max-prealloc和实时显存让步；真实工作足够时降负载，采样/显存/主程序异常时收敛并告警。控制参数、分配、启停、强度与吞吐写入本次JobID日志，退出清理。不能为避免取消制造OOM，也不能在活动旧作业根改运行代码。
- 系统取消先核对最终状态、精确日志和阶段，区分利用率、抢占、程序错误与未知原因；不把旧排队Reason当取消归因。恢复核验完整optimizer、scheduler、随机状态和实际LR，保留旧JobID，使用新提交清单。保护有效须由持续更新、完整保存及长作业验收证明，启动成功或短测不足以宣称彻底解决。

## 6. 监控、修复与结论

- `sacct`顶层及`.batch`用于最终状态，`squeue`只表示活动队列。历史任务从队列消失不等于失败。日志路径从提交脚本/清单或实际作业定义定位，不凭名字猜测。
- 读取真实结果后区分：本地检查、远端基础设施、训练更新、代理奖励、固定验证、独立测试和人工质量。`COMPLETED/0:0`、HTTP成功、有限梯度或断点存在均不能替代后一级结论；没有对应证据就明确未验证。
- 报错先定位首个实际失败，沿已授权范围实施最小修复与针对性验证，并更新相关运行记录。方向明确时不重复请求许可；存在目标分歧、缺关键输入或需要新授权时才询问。科学指标未改善、零通过或语义拒绝先审计真实原因，不放宽标准或盲目扩大任务。
- 控制变量、分组划分和完整配对分母必须保持真实。单视频窗口、同一pair或少量槽位不能称跨视频泛化或统计显著；代理评分与人工gold分开。具体损失、归一化和生成端同步以实际版本和运行证据为准。
- 用户可见汇报说明当前状态、JobID、关键结果、未验证边界和下一步；不主动罗列指纹数值或把多项基础检查包装成多次smoke。轮询遵守当前 `AGENTS.md` 的长等待要求。

## 7. 文件传输

- 上传只同步本次授权的明确文件，先创建准确远端目标目录；保护远端源码、本地dirty state和历史产物。窄SFTP或已验证Git流程完成后检查接收文件、Git状态及适用的脚本语法，不扩大成整仓/模型/缓存上传。
- 从Torch下载只使用交互式SFTP，顺序固定为 `sftp` → `lcd` → `cd` → 逐文件 `get` → `bye`，全部路径/文件明确；不使用scp、rsync、HTTP或GUI替代。用户明确要求公开URL视频时，仅该视频按URL获取可例外。
- QA Markdown与审核视频的内容、目录和标注合同按工作区专门章节执行；只有相关交付任务才读取，不作为连接或训练状态查询的前置条件。

## 8. Runbook的最小要求与自检

按实际任务保留设置/范围、直接可执行操作、JobID产物、验收与失败处理；不必套19节模板、解析表或多个Gate。交付前确认：

1. 来源真实：当前仓库、配置、输入、资源及脚本可核验，旧实验值没有冒充本次值。
2. 命令完整：运行位置清楚、独立成立、无未解析占位符、不关闭登录会话；提交使用 `--parsable` 并立即记录JobID。
3. 工程安全：存储、受影响环境/媒体、必要运行验证和GPU保护覆盖已知风险；不会覆盖历史或重复提交。
4. 边界清楚：检查/训练/指标/质量分别说明，未执行阶段不写通过，估时有实际依据。
5. 范围准确：仅包含用户授权的任务，不默认新增hash、冻结合同、baseline、Gate、计划文档或额外GPU实验。新增保护机制须说明具体失败场景及普通机制为何不足。
